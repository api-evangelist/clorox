# The Clorox Company

> Multinational consumer-packaged-goods manufacturer (Clorox, Pine-Sol, Liquid-Plumr, Glad,
> Kingsford, Brita, Burt's Bees, Hidden Valley). Clorox runs NO developer program and publishes
> no API documentation. It does, however, serve a small set of undocumented, anonymous,
> first-party REST endpoints from its corporate WordPress site that expose regulated product
> disclosure data — Safety Data Sheets, cleaning-product ingredient disclosures, CPSC general
> conformity certificates — plus a live job feed. This file was GENERATED by API Evangelist from
> probes of Clorox's own hosts on 2026-09-05; Clorox does not publish an llms.txt.

## Machine-readable API surface (undocumented, anonymous, first-party)

Base: https://www.thecloroxcompany.com/wp-json

- [WP REST discovery document](https://www.thecloroxcompany.com/wp-json/): 280 routes across 12 namespaces; self-identifies as "The Clorox Company". The two first-party namespaces are tcc/v1 and clorox-security/v1.
- [tcc/v1 namespace descriptor](https://www.thecloroxcompany.com/wp-json/tcc/v1): 8 routes, with methods, argument names and required flags.
- [Safety Data Sheets (XML)](https://www.thecloroxcompany.com/wp-json/tcc/v1/sds-xml): index of SDS documents as `<safety-data-sheets><sds><name><url>`. No parameters.
- [Cleaning product ingredient disclosures](https://www.thecloroxcompany.com/wp-json/tcc/v1/cleaning_labels): optional `country` (default "United States"), `brands`, `search`.
- [General conformity certificate lookup](https://www.thecloroxcompany.com/wp-json/tcc/v1/general_conformity): requires `upc` and `lot`.
- [Job requisitions](https://www.thecloroxcompany.com/wp-json/tcc/v1/job-search/job-query): no parameters. Detail at `/job-search/job-detail` requires `job_unique_identifier`.
- [DSAR country regions](https://www.thecloroxcompany.com/wp-json/tcc/v1/dsar/countryRegions): takes `countryCode`.

## How to call it safely

- No credential is needed for reads. The only advertised auth is WordPress application passwords, which is an editorial CMS credential, not a consumer credential.
- There is no rate-limit header and no published limit. Be conservative; there is no runtime signal telling you to back off.
- ERROR HANDLING IS INCONSISTENT. WordPress core routes put failures in the HTTP status (400 with `{code, message, data:{status, params}}`). The hand-written routes `dsar/countryRegions` and `clorox-security/v1/is-do-not-share` return HTTP **200** with a body of `{status: 100, message: "<error>", data: []}`. Read `body.status`, not just the status line.
- No idempotency key exists on any of the three write operations, and none of them can be reversed. Do not retry a POST.
- These endpoints back a public website and carry no support commitment, no SLA, no status page and no deprecation policy. Clorox may change or remove them without notice.

## Gated surfaces (do not expect access)

- `https://api.clorox.com` — a MuleSoft Anypoint gateway (403 at root, 404 everywhere else). Partner/supply-chain integration; no public credentials, no public contract.
- `https://anypoint.mulesoft.com/exchange/portals/clorox/` — Clorox's Anypoint Exchange public portal is provisioned and `"status":"enabled"`, but publishes **zero** assets.
- Retail and supply-chain integration with Clorox runs over EDI and partner agreements, not a public API.

## Not published

No OpenAPI. No GraphQL. No AsyncAPI, webhooks or event stream. No WSDL. No gRPC/protobuf. No MCP server. No A2A agent card. No SDK in any language. No `/.well-known/` document on any host. No status page. No developer portal, changelog, sandbox or pricing.
